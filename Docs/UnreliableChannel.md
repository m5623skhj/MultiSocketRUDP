# 비신뢰성 채널 (프로토콜 v2)

서버 `RUDPSession`과 C++ `RUDPClientCore`의 `SendUnreliablePacket(IPacket&)`으로 콘텐츠 패킷을 보냅니다. ACK, 재전송, 신뢰성 수신 윈도우 및 누락 패킷 대기를 사용하지 않습니다. 소켓과 송신 스레드는 기존 경로를 공유합니다.

## 송수신 정책

- 세션마다 신뢰성 송신과 독립적인 64비트 송신 번호를 사용합니다. 최초 송신 번호는 1입니다.
- 수신은 최초 인증 성공 패킷을 번호에 관계없이 수용합니다. 이후 마지막으로 수용한 번호 이하인 패킷은 버리고, 더 큰 번호는 누락된 번호를 기다리지 않고 처리합니다.
- `CORE.UNRELIABLE_QUEUE_CAPACITY`는 패킷 개수이며 기본값은 64, 허용 범위는 1~65535입니다.
- 송신 대기열이 가득 차면 가장 오래된 미송신 패킷을 해제하고 새 패킷을 수용합니다. 이때 송신 API는 `true`를 반환합니다. 이는 큐 수용 성공이며 전달 보장이 아닙니다.
- 서버에서 다음 송신으로 보류한 패킷도 미송신 한도에 포함합니다. 이미 송신 버퍼에 복사했거나 소켓 송신을 시작한 패킷은 드롭 대상이 아닙니다.
- 두 송신 큐에 데이터가 있으면 신뢰성/비신뢰성 패킷을 번갈아 선택합니다.
- 서버는 기존 패킷 핸들러로 전달합니다. C++ 클라이언트는 `GetReceivedUnreliablePacket()`으로 별도로 꺼냅니다. 반환 버퍼의 읽기 위치는 `packetId`이며 호출자가 `NetBuffer::Free()`해야 합니다.
- 클라이언트의 애플리케이션 수신 대기열에도 같은 개수 한도를 적용하고, 가득 차면 가장 오래된 대기 패킷을 해제합니다.
- 종료 시 비신뢰성 대기 버퍼를 정리하고 새 세션에서는 송수신 번호 상태를 초기화합니다.
- 순서가 맞는 하트비트는 수신 시 내부에서 해제합니다. 누락된 번호나 아직 소비하지 않은 신뢰성 콘텐츠를 건너뛰지 않으며, 콘텐츠 소비 직후 뒤따르는 하트비트도 처리합니다. 종료 시 신뢰성 수신 큐의 남은 버퍼도 해제합니다.
- 클라이언트의 서버 생존 검사는 채널과 애플리케이션의 패킷 소비 여부에 관계없이 인증된 수신 횟수로 판단합니다. 인증 실패 패킷은 생존 상태를 갱신하지 않습니다.
- 예약 패킷 교체로 송신 스트림이 비게 되면 송신 상태를 해제한 뒤 큐를 다시 확인하여 새 패킷의 송신을 재개합니다.

## 패킷과 nonce

패킷은 기존 콘텐츠 패킷과 같은 헤더·번호·packetId·본문·인증 태그 배치를 사용하며, 타입은 `UNRELIABLE_SEND_TYPE`(7)입니다. 기존 세션 키와 salt를 사용합니다.

방향값은 기존 0~3에 `CLIENT_TO_SERVER_UNREL`(4), `SERVER_TO_CLIENT_UNREL`(5)를 추가합니다. 12바이트 nonce는 다음과 같습니다.

```text
nonce[0]    = (direction << 5) | (salt[0] & 0x1F)
nonce[1..3] = salt[1..3]
nonce[4..11]= sequence (big endian)
```

같은 세션 키에서 방향과 채널이 다르면 같은 번호라도 nonce가 다릅니다. 64비트 번호 소진·순환에 대한 방어는 이번 범위에서 제외했습니다. 번호 소진 시 nonce를 재사용하게 되므로 그 전에 세션 키를 교체하는 등의 후속 대응이 필요합니다.

## 호환성

UDP 연결 요청의 ACK가 유실되면, 서버는 이미 연결된 동일 주소·포트의 유효한 연결 요청에 ACK만 다시 보냅니다. 접속자 수 증가·연결 콜백·수신 상태 초기화는 최초 연결에서만 수행합니다. 봇 테스터도 최초 연결 ACK에서만 연결 콜백과 생존 검사를 시작하며, 중복 ACK나 종료 중인 세션의 ACK로 연결 처리를 반복하지 않습니다.

TLS 핸드셰이크 직후 클라이언트가 암호화된 4바이트 big-endian 버전 `2`를 보냅니다. 서버는 버전을 확인한 뒤에만 세션을 예약합니다. 버전이 다르거나 5초 내에 받지 못하면 브로커 연결을 닫습니다. 브로커 응답에도 기존 응답 앞에 32비트 버전 필드(NetBuffer의 기존 little-endian 형식)를 추가하고 클라이언트가 확인합니다.

구버전 클라이언트는 호환되지 않습니다. C++ 클라이언트와 C# BotTester 모두 v2를 사용하며, `CoreTest/ProtocolInteropV2Vector.json`의 동일한 10개 벡터를 각 언어의 테스트에서 확인합니다. v2 벡터는 .NET AES-GCM으로 별도 계산하여 Windows BCrypt 구현의 결과와 비교합니다.

## C# BotTester

BotTester의 비신뢰성 송신은 헤더와 인증 태그를 포함한 최종 크기가 65,507바이트를 넘으면 버퍼·송신 번호를 변경하지 않고 `false`를 반환합니다. 소켓의 크기 제한 오류도 해당 패킷만 버리고 처리합니다. 이 한도는 IPv4 UDP 자체의 상한이며 서버의 수신 버퍼나 경로 MTU까지 보장하지는 않습니다. 중복·오래된 비신뢰성 응답은 RTT 측정값을 갱신하지 않습니다.

`SendUnreliablePacket(NetBuffer, PacketId)` 또는 송신 노드 설정의 **비신뢰성 전송**을 사용합니다. 기존 그래프는 신뢰성 전송을 유지합니다. 송신 선택은 응답 채널을 강제하지 않으며 서버 핸들러가 응답 송신 방식을 결정합니다.

BotTester는 비신뢰성 송신·수신 대기열을 각각 64개로 제한합니다. 가득 차면 가장 오래된 대기 패킷을 버립니다. 송신은 같은 UDP 소켓을 사용하는 별도 비동기 작업이 처리하고, 수신 콜백은 기존 신뢰성 콜백과 같은 처리 작업에서 채널마다 하나씩 실행합니다. 신뢰성 수신의 누락 대기는 비신뢰성 수신을 막지 않습니다. 하트비트는 내부에서 처리하며, 서버 생존 검사는 인증된 수신 횟수를 사용합니다.
